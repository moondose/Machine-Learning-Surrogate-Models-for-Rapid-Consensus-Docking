# Surrogate model training

Train the project's two final descriptor MLPs using the Morgan + RDKit 2D/3D matrix. Keep `model_utils.py`, both trainers and `configs/` together. The scripts run independently of the original training workspace.

## Dependencies

Python 3.9+, PyTorch 2.3 or later, NumPy, pandas, SciPy, scikit-learn and Matplotlib. The CPU smoke test used the `submo_sampling` conda environment and PyTorch 2.5.1.

```bash
python -m pip install numpy pandas scipy scikit-learn matplotlib
```

Install the appropriate PyTorch build for your CPU or GPU environment.

## Inputs and alignment

The descriptor directory contains:

```text
X_features.npy
feature_names.csv
zinc_ids_aligned.csv
```

`zinc_ids_aligned.csv` must contain a unique `zinc_id` per feature row. `feature_names.csv` defines the matrix column order. The supplied configurations expect 2274 columns: Morgan radius-2 fingerprints plus RDKit 2D/3D descriptors.

Each target directory contains the NPY generated by the target builder and its `target_ids.csv`, with a `molecule_id` column. Trainers align targets by molecule ID to descriptor order and exclude missing/nonfinite targets. Use `--target-ids` and `--target-id-column` to select another ID table. Percentile training also accepts legacy NPZ archives containing a target array and `zinc_id`.

## Mean binding energy

```bash
python train_mbe.py \
  --descriptor-dir /path/to/descriptors \
  --targets /path/to/targets/mbe/y_mbe.npy \
  --output-dir /path/to/new_results/mbe
```

The MBE network uses Linear → BatchNorm → activation → Dropout hidden blocks. It standardizes features and the target using each training fold only, trains with MSE, and selects checkpoints by lowest validation MSE. The learning-rate scheduler also follows validation MSE.

`configs/mbe.json` retains the settings recorded in the project's `mbe_batch_1024_lr_0.01` experiment: hidden layers 2048/1024/512, SiLU, dropout 0.4, SGD with momentum 0.9 and Nesterov, LR 0.01, weight decay 0.0001, batch 1024, 200 epochs, 10 folds and seed 42. Early-stop patience is 20 and scheduler patience is 4.

## Percentile consensus

```bash
python train_percentile_consensus.py \
  --descriptor-dir /path/to/descriptors \
  --targets /path/to/targets/percentile/y_percentile_consensus.npy \
  --output-dir /path/to/new_results/percentile
```

This network uses Linear → LayerNorm → activation → Dropout hidden blocks. It standardizes features and the target within each training fold, uses Smooth L1 loss (beta 0.25), clips gradient norm at 5, and selects checkpoints by validation top-1% NDCG. Scheduling and early stopping follow NDCG. Lower target values and predictions are better. The trainer consumes precomputed percentile targets without recomputing ranks.

`configs/percentile_consensus.json` retains the final diverse-sampling experiment's settings: hidden layers 1024/512/256/128, ReLU, dropout 0.4, AdamW LR 0.0001, zero weight decay, batch 1024, 80 epochs, 10 folds and seed 42. NDCG minimum improvement is 0.00001, scheduler patience is 4 and early-stop patience is 10.

## Execution controls

Both scripts accept `--config`, `--folds`, `--epochs`, `--threads`, `--cpu`, `--precision` and `--cache-device`. Explicit CLI training controls take precedence over corresponding saved settings. Use `--help` for each trainer's options.

CPU execution automatically uses FP32. On CUDA, automatic precision follows the saved AMP configuration. Normalized fold caches require approximately `4 × rows × (features + 1)` bytes of RAM. `--cache-device cuda` additionally retains these data on the GPU. The default cache is CPU RAM.

Choose a new output directory for each experiment. Use `--max-rows` for a short smoke test.

## Saved artifacts

| Artifact | Purpose |
| --- | --- |
| MBE: `fold_N/best_model.pt`, `fold_N/metadata.npz` | Best fold weights, exact feature/target scalers, architecture and split row indices |
| Percentile: `fold_N_best_model.pt`, `fold_N_metadata.npz` | Best fold weights, exact scalers, architecture, split rows and NDCG selection settings |
| `feature_names.csv` | Prediction feature schema and order |
| `model_config.json`, `training_config.json` | Effective model settings and full run arguments |
| `input_ids.csv`, `input_manifest.json` | Source row IDs, alignment counts and feature-schema hash |
| `fold_assignments.csv` | Each included descriptor row's validation fold |
| `out_of_fold_predictions.csv` | Held-out predictions in original target units |
| `fold_metrics.csv`, summary JSON | CV and OOF metrics |
| Fold histories and PNG plots | Training and validation learning curves |

Load MBE state dictionaries into `model_utils.DockingMLP`, and percentile state dictionaries into `model_utils.SearchConsensusMLP`. At prediction time, apply the corresponding fold's `x_mean`/`x_std` and invert its `y_mean`/`y_std`, then average predictions across folds.

## Validation

Both trainers completed a two-fold, two-epoch CPU smoke test on descriptors from ten ZINC molecules, using small hidden layers for the test. Checks covered reversed target ID order, unavailable target exclusion, training-fold-only scalers, and reloading saved weights/scalers to reproduce the OOF predictions.

## Target provenance

When the target builder writes `summary.json` beside its arrays, training copies the selected target definition, engine set, score directions and ranking population into `input_manifest.json` and `model_config.json`. Keep the target summary beside its arrays. A target file whose declared recipe does not match the requested training response is rejected.
